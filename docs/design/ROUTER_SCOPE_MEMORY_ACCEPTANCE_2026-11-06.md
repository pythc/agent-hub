# 第一步验收规格：归属、共享边界、上下文和迁移

版本：v1，2026-11-06（Asia/Shanghai）。**以下是待实现后执行的验收用例，不是已通过的测试报告。** 本轮仅完成规格与文档复核，没有新增或运行这些测试。

依据：[设计 D01–D12](ROUTER_SCOPE_MEMORY_V1_2026-11-06.md)、[迁移 M0–M7](ROUTER_SCOPE_MEMORY_MIGRATION_2026-11-06.md)、[外部组件契约](MEMORY_BACKEND_RESEARCH_2026-11-06.md)。

## 1. 验收层级与判定

| 层级 | 证明什么 | 不能替代什么 |
| --- | --- | --- |
| L1 状态与契约测试 | 归属、权限、版本、幂等、恢复的确定行为 | 真实模型是否理解请求 |
| L2 故障与并发集成 | 数据库、队列、接入/记忆替身、崩溃窗口的结果 | 真实飞书收发、原生历史恢复 |
| L3 真实模型与原生线程 | 实际上下文、跨话题接续、纠错和模型配置 | 真实群传输和成员权限 |
| L4 两个真实受控群 | 同一任务跨群、正确受众、真实回复和恢复 | 所有组织场景的普遍正确性 |

结果只使用 pass / fail / blocked / not_run / not_applicable。所有必需用例须 pass；blocked 和 not_run 都不能发布为通过。P 组仅在启用外部组件时强制；未启用需记录 not_applicable，不能算通过。L1/L2 使用模型替身必须明确标记，真实层需记录实际后端/模型/effort。

否定结果要有实际查询/调用计数、上下文捕获和目标回读证据，不能只断言“Router 没有提到私有内容”。内部 queued/stored、记忆索引 accepted、设置已保存都不等于执行或交付完成。

## 2. 固定合成数据集

两个 tenant：T1、T2；T2 使用与 T1 相同的群名、显示姓名、部分外部数字 ID，以验证命名空间。

T1：项目 P1 的 Router R1 绑定群 G1、G2；项目 P2 的 Router R2 绑定 G3。T2 的 R3 绑定 G4。Owner O 能管理 T1，但没有默认个人私有正文阅读权。成员 A 同时在 G1/G2，B 只在 G2，C 只在 G1；T2 中有一个显示名同为 A 的人。所有身份来自连接器夹具，不来自消息正文。

固定事实：F1“G1 内部预算为 73”仅 G1；F2“项目交付日为 11 月 20 日”已正式发布给 P1 两群；F3 为 A 的私人偏好；F4 有两份独立证据；F5 必须联合两份材料才能成立。F6 是由 F1/F2 生成的混合摘要。给每份材料放入不同可辨识标记，用于检测模型入参、搜索片段和外发内容。

固定任务：K1 在 G1 创建，G2 初始无 request/result 许可；K2 已人工停止；K3 正在运行；K4 人工接管；K5 外部交付 uncertain；K6 已完成；K7 授权依据缺失。每个任务有固定 Worker/原生线程/目录/参数/操作回执，迁移后逐字段比较。另备多任务同话题、空状态库及含未知插件记录的库。

时间使用可控时钟，展示时区为 Asia/Shanghai；并发与崩溃测试用显式屏障，避免靠随机 sleep 通过。真实层使用明确选定的测试群与合成内容，不把上述假身份当作真实成员。

## 8. 发布前实测场景

L3 至少用真实 API 后端和原生 Codex CLI 各跑一次完整上下文流程，记录实际可用模型。延续既有组合的实测配置目标为 Terra/medium Router 与 4 个 Sol/high Worker；模型若不可用，结果标 blocked，不静默替换后宣称该组合通过。四个 Worker 的存在不要求把每个简单问题拆成四份；并发身份测试另用四个独立任务。

L4 使用两个明确获准测试群，执行以下顺序：

1. 在 G1 提出任务，取得真实任务、原生线程及原群回复证据。
2. G2 未获任务共享时引用它，确认不暴露内容；建立指定任务入口和共享事实后再次引用，确认继续原任务。
3. 在 G1 更新一项已共享决定，验证 G2 能区别当前决定、待复核共享版本和历史版本。
4. 加入仅 G1 可见的合成标记，核对 G2 的实际模型上下文与最终群消息都没有该标记。
5. 排空执行后重启指定测试宿主，继续原任务；核对原 Worker 身份、未读输入与出箱。
6. 撤回共享、清空测试记忆，完成相应受控恢复演练；检查旧线程和索引没有恢复可见性。

群里可以使用明确自然语言请求或当前显式入口。无 @ 的自动判断属于第二步，不能把本期沿用显式准入解释为已完成主动模式。Worker 不取得外部聊天发送工具；群内消息必须可追溯到 Router 的授权出箱。

## 9. 证据、数据规模与准出要求

每个用例记录：用例 ID/版本、代码与配置指纹、fixture、时钟、操作 ID、前后状态摘要、任务/线程/模型身份、context manifest、模型输入捕获、外部调用计数和回执、故障点及恢复结果。记录含私有测试正文时留在受限证据目录；普通报告使用标记和指纹。

检索规模检查固定为两个 tenant 合计 10,000 个事件、2,000 条事实、200 个任务，混入相同关键词与撤回记录；每种查询跑 100 次，报告冷/热路径延迟分布、扫描量、模型入参大小及成本。数字是本项目的测试负载，不是上游性能结论。L1/L2 期间模型调用次数和副作用数必须与用例预期一致。

上下文预算测试至少使用一个小预算配置，断言请求不超硬上限、必要授权与工具回执不被截断、truncated 如实报告。检索结果按限额分页；禁止先全库正文灌入模型再“让模型筛选”。模型时延受所选服务影响，本期要求提交实测分布，不预填未经测量的性能承诺。

准出要求：

- R/F/C/G 所有必需确定性用例通过；启用提供方时 P 组通过；L3/L4 的关键场景单独通过。
- 固定夹具下：零重复任务/已完成效果重放、零越界模型入参/外发、零静默丢弃迁移记录、零停止任务意外恢复。只对已执行测试范围作结论。
- 真实模型的事实采纳、冲突识别、召回结论须逐条对照标注依据，不让同一个模型自评分替代验收。失败项进入修复或保持候选状态，不能降低权限断言来换取通过。
- 上游核心回归及现有 Router/后端/连接器相关回归通过；vendor 文件若有改动，先修改设计与差异说明，本期不默认接受。
- 至少完成一次 M5 崩溃恢复、一次有外部效果后的回退决策、一次清空后的备份恢复演练。
- 本次修改以外的现有运行实例，配置/状态和工作负载保持不变；验证记录要能证明这一点。
