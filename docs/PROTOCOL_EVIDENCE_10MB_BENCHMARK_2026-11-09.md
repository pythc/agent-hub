**实现与边界**

- 原生协议按 item／call 身份合并同一记录的 raw、磁盘和待确认副本；相同文字的不同调用仍分别保留。未落盘消息、steer／refresh、工具返回和无法确认身份的数据保守计数。压缩使用 replacement history；原有来源消费回调不因 RPC 确认提前发生。
- 原生工具目录须包含完整、相同的实际声明，才取消其配置副本的单独计数。只遍历真实目录数组及 `namespace.tools`，不把同名工具、schema 的 `const`／`examples` 或未知包装当作覆盖。
- 在原生输出通知到达时检查预算；同批后续工具执行前即记录超限状态。托管工具权限、当前 thread／turn 归属、停止和撤销检查保持。
- 执行证据仅在传输副本中共享重复 stdout／长行的完整文字。每个 job、命令、退出码、策略、hash 和完整性标记仍独立存在；每个引用都带完整原文，缺失引用拒绝恢复。必须与原始 JSON 逐字还原一致，原件持久化格式未变。
- 全新验收／规划／复核输入的完整证据额度提高为 `min(512KiB, 有效上下文预算的四分之一减基础输入)`；放不下的整件仍走原有无缺口 Unicode 分页。原件快照本身的 512KiB 上限未改。模型返回且重新验证当前授权／快照后才确认内联交付。
- scope 默认及允许最大值为 **10,000,000 字节（十进制 10MB）**，已有显式较小预算保留。输出／工具预留、API 后端自身上限和 HTTP 请求限制保持。该值不是 token 数、provider 窗口、进程内存或磁盘配额；本轮没有更改现有实例的 scope。

原始目标、授权引文、每一条验收条件、必需证据引用、独立方案复核、次数限制、人工停止、工具／来源范围和任务侧网络政策保持。新 `requiredEvidenceIds` 只明确列出原先已经要求引用的全部失败证据，不删证据、不降低标准、不增加重试。

既有 token 统计和 Agent board **0.1.4** 沿用；缓存输入属于输入、推理属于输出，不重复相加；失败尝试也保留。看板仅接收数值汇总，不新增原始提示词或凭据访问。

使用全新目录，顺序运行，禁止指向现有实例的 state。以下会实际消耗模型用量。A／B 必须使用同一冻结 harness，代码根分别指向 `65a9659` 和 `8d6ef06`，均显式传入 `10000000`。


02-a／02-b 用 `replan`；03-b→03-a 用 `repair`；04-b→04-a 用 `replan`。保留失败和顺序。

```sh
python3 examples/compare-evidence-cost.py /absolute/fresh --native-index /absolute/codex/state_5.sqlite --pair repair:01-a:01-b --pair replan:02-a:02-b --pair repair-repeat:03-a:03-b --pair replan-repeat:04-a:04-b
```

原生对账只适用于这组 fresh-thread 实验，取每个拥有线程的最终累计快照一次并核对 step 数；不相加每条累计通知。省略 `--native-index` 时保持未验证。不同 source hash 是有意的处理变量；harness／业务条件不允许不同。

缓存状态、provider 负载、模型选择的执行／取证步骤均存在波动；未固定 provider 随机种子。小样本与固定任务图不能证明所有生产 A2A 场景都有相同节省。字节估计修正本身不等于实际 prompt token 减少，本轮端到端结果评价的是整组协议／交接改动，未做单项消融。

原生预算目前仍读取、解析拥有的整份 rollout；10MB 序列化额度不限制历史文件大小、解析开销或 RSS。模型自身上下文窗口也独立存在。当前试验不能证明长期大历史或任意 provider 均不会超限。
