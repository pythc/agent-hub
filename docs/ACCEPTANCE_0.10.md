# AgentHub 0.10.0：按实际入口配置与验收

日期：2026-11-05。目标是让助手进入用户原有的工作软件，让部署者完成一次配置，让日常使用者在原会话交代工作和接收成果。网页聊天不再是默认配置终点。

## 本轮交付

- 默认双角色入口：使用已有助手；部署或管理助手。普通使用者读取所分享的操作说明，无模型、密钥、宿主配置或工单要求。管理 API 独立认证，角色选择本身不授予权限。
- 管理工作台优先显示待人工处理事项和已接入软件，支持同时连接多个入口。英文主要、简体中文完整，保留原高级设置、资源、提示词、作业和历史。
- `npm ci` 后运行 `./start.sh setup`，不用编写 JSON。默认私有目录、专用只读文件夹、自动选择并记住端口，再次运行复用已有宿主。预装 Node 和源码依赖仍是实际要求，尚不是可双击的桌面安装包。
- 启动时提供一次性短期管理链接，换取同源 HttpOnly 会话，刷新不再要求重复找令牌文件。不同实例的会话按端口区分；长期管理令牌不放 URL 或浏览器存储。进程重启后获取新链接。
- 按平台预检：飞书复用 bot 登录并列出可选群；无 CLI 时支持直接检查 App ID/Secret；企微使用 API 模式智能机器人长连接；客户端按钮安装命名条目且保留备份；Codex 使用官方 CLI；GitHub 复用原登录。
- 缺少模型时在当前入口页完成“Codex / 已有连接 / API 服务”的填写、检查、保存。三种 API 协议全部保留，不创建新的网页聊天来源，不丢弃已有平台入口或旧会话。
- `agent_request` 为客户端 AI 自动处理来源、讨论和请求标识，返回准确的后续查询参数。`agent_status` 提供精简结果，可按讨论/请求过滤；完整资源接口保留。
- 验收分别记录收到、准入、执行、回复。生成配置、连接成功和保存完成都不是实际任务验收。MCP 必须真正取回回复；网页查询不代替客户端读取。

## 实机发现并修复的问题

1. **飞书身份读取。** 当前本机 CLI 的通用 `bot/v3/info` 输出丢失了顶层 bot 对象，产生空 data。改用 `auth status --json --verify`，要求实际验证过的 bot 身份，不把缓存的个人用户身份当机器人。真实预检重新得到 bot 身份与授权目标群；增加缺失验证拒绝用例。
2. **澄清回复。** 宿主在 `engine.reply(purpose=attention)` 时漏传当前 question，触发原型核心的正确拒绝。现原样传入已登记问题，正常澄清保持等待人处理，不再被错误隔离为执行不确定。原型核心未修改。
3. **简短测试标记。** 精确匹配宿主登记、未过期的短测试语句时，给路由和执行传递可信连接测试上下文，说明它不是工单编号；仍经过真实授权和模型执行。原消息保持原样，含标记的普通业务请求不被改写，未授权用户仍被拒绝。
4. **触发引用兼容。** 工作模型曾将 `trigger/<id>` 资源引用传给 ACK。宿主现在接受这种确切引用，再由原型核心验证它是否属于本工作；不能因此访问无关请求。原始 ACK 仍幂等。
5. **复制即可走后台。** 客户端验收语句明确要求用 `agent_request` 转交正文，并按返回的标识查询 `agent_status` 和展示实际回复。正文中“不调用工具”的约束仅作用于后台助手，避免前台 AI 直接回答而绕过接入。最终将页面显示的完整英文语句原样交给既有 Codex 原生聊天，实际调用请求和状态工具后显示 `Connection verified.`，宿主四步回执均确认。飞书、企微和 GitHub 保留原软件中的直接消息形式。
6. **真实结果可读。** 全量历史在 VS Code 中溢出到临时文件，模型无法看到成功回复。普通 MCP 状态现在只返回有限的工作摘要，支持精确过滤，长结果显式给出资源路径。普通 HTTP 管理状态保留完整结构。新回归同时覆盖响应大小、来源桥匹配和网页轮询不能制造回执。
7. **管理会话与共享状态。** 本机不同端口不再互相覆盖管理 cookie；跨源写入被拒绝。客户端邀请状态和手动通用 MCP 的已验证状态依据真实安装/调用证据，修复了只按办公 Source 推导造成的错误状态。

飞书恢复前已完整读取失败的原生 turn：只有限定范围的读取和幂等 ACK，没有不确定的文件写入或发布。随后操作员补充测试标记的含义，受控重试沿用原 native thread，并在原话题得到“接入验收成功。”。本轮保留首次错误和恢复过程，不修改原消息、不伪造新的人类消息、不自动扩大允许列表。

## 易用性与界面核验

“前端专家”完成设计和 UI，宿主集成方另行进行了真实入口核验。隔离 UI 主流程覆盖：两种角色、一次性配对与刷新恢复、英文/中文、缺少模型、API 草案检查保存、飞书选择群、企微缺权限、客户端配置保存后继续验收、分享可复制说明、失败邀请保留输入、冲突和高级设置来回切换。检查了桌面和 390/320px 窄屏、焦点与主要键盘操作，已检查状态没有横向溢出。未宣称完成独立新手用户研究或全面无障碍认证。

真实 4335 工作台另外核对六个入口的回复状态、已有 Codex 安装/登录检查及保存后保留入口。服务商测试语句也提供英文/中文，长期令牌和密钥不出现在截图。仓库 `docs/ui/previews` 是明确标注的**隔离 UI fixture**；真实平台原始读回、群消息、客户端截图与凭据保留本机，不公开上传。

普通员工的最低路径是收到一段说明，在已有软件找到助手并发任务。管理员仍须完成平台创建/审核、成员授权或客户端首次信任。当前分享主要产物是可复制文字，localhost 链接只是同机/安全隧道下的可选指引，不能当作公网团队门户。远端桌面客户端仍需正确的桥接程序、凭据路径和同端口 SSH 转发；尚无零配置跨机器安装器。

## 回归、升级与范围

- TypeScript 和 **333 项测试**通过，含 113 项上游核心用例；15 个 vendored 核心文件与原基线 SHA-256 一致。
- 14 种客户端配置经真实 stdio SDK 发现 21 个工具，并读取状态/资源成功。对未安装的其他客户端，这一结果只证明协议桥与配置生成；产品 UI、账号和信任流程不计为已实测。
- 模型页对 OpenAI Responses、Chat Completions、Anthropic Messages 分别完成隔离 HTTP 检查、受管配置保存、重启回读和备份校验。真实商业 API 调用仍未验证。
- 新来源/模型配置覆盖版本冲突、忙碌拒绝、受控重载失败回滚、私有凭据、崩溃日志恢复，以及已有来源与原生会话保持。客户端覆盖不覆盖他人条目、幂等、冲突及有后续用户编辑时拒绝回退。
- Linux 结果与环境见 [Linux 文档](LINUX.md) 和本轮机器可读报告。ARM64 Linux 内核、UID 1000、独立 Bubblewrap 及完整用例，不是裸机/AMD64/全部发行版验收。
- 用真实归档的 0.9.0 源码完成 0.9.0 → 0.10.0 → 恢复升级前备份 → 再升级。schema 都为 5，同 schema 兼容没有伪称“旧版拒读”；原 native identity 保留。恢复不撤销文件、已发送消息、Git 推送或合并。受管模型/办公密钥和来源的恢复另有专门回归。
