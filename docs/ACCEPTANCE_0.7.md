## 本轮发现并解决的问题

- Linux 用例此前只在 macOS 执行。现在实际启用 Bubblewrap 分支，生命周期测试也使用 Linux 驱动，不再依赖容器中不存在的 Codex。
- Docker 默认策略阻止嵌套沙箱。区分 user namespace 和 proc 挂载限制；只在隔离验收容器调整外层策略，不使用特权容器，不修改主机全局策略。新增真实进程 setup 探针，依赖存在但不可运行时不会误报就绪。
- 修正测试对独立 tmpfs 的错误假设：能在沙箱 `/tmp` 创建文件不等于写穿宿主；测试同时验证宿主原文件不可读、内容未变。
- 原有“讨论与事件”先过滤父讨论，导致事件正文匹配仍被隐藏。现在按讨论或关联事件匹配，浏览器复现前失败、修改后通过。
- 企微连接关闭后的 SDK 延迟事件曾访问已关闭数据库。关闭流程现在先等待接收任务，再释放上下文，真实 SDK 测试不再出现未处理异常。
- 附件先完成落盘再登记可用状态，每个附件持久化缓存回执；保留平台返回的扩展名，修复长中文名称按字符截断造成的文件系统长度问题。
- 修复宿主环境凭据文件位于可读目录时的暴露：独立沙箱屏蔽真实文件目标，原生 Codex 权限配置增加拒绝项，资源接口拒绝读取；macOS/Linux 真实命令验证了文件和符号链接不可读、原文件未改变。保护针对指定凭据路径，不覆盖任意复制品或硬链接。
- 移除企微群配置后拒绝继续读取/投递该群；无目录接口的来源不显示不可用的目录同步操作。
