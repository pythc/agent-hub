# AgentHub 目标验收、返工与依赖调度

本轮按“结构化验收 → 独立验证 → 失败返工 → 任务依赖图 → 分类恢复”的顺序实现。采用 AgentHub 自身的 Runtime、SQLite 记录、任务归属与消息投递机制；没有复制 LobeHub 实现代码，也没有修改 dsh-core。

## 完成的行为

`router_goal start` 可以声明 `criteria` 和 `nodes`。每项 criterion 包含说明、相对文件路径或知识文档 ID，并可选确定性检查：文件存在、文本包含、JSON Pointer 对应值严格相等。每个节点声明 Worker、依赖及所负责的 criterion。启动时拒绝环、未知依赖、重复节点、未覆盖验收项及越界 Worker。

Worker 的 `ready` 被保留为候选交付，任务在总体验收之前保持开放，原始成功消息不会立即发布。宿主记录任务 assignment、输入 revision、合同及交付物内容摘要；程序检查直接读取真实文件。语义检查在新建的验证会话中执行，只开放读取该轮不可变快照的 `goal_evidence` 工具。证据通过按工具预算限长的 Unicode 分页返回，宿主记录连续读取进度，必须读完整个内容后才认可引用。通过的语义判定必须实际读取并引用该项声明的全部文件/文档；Worker 自述不能代替声明的交付物。整体目标还有单独的最终语义核验，并必须读取宿主执行证据：受管命令文本、退出状态、实际启动时的沙箱/网络策略、已观察的工具调用和外部工具回执。只投影必要策略，不暴露宿主私有配置；权限重建隔离的历史不会重新导出，证据不完整会明确标记。

验证结束前重新检查权限、输入版本和交付物摘要。旧结果不能覆盖新输入。暂停期间可保存已在执行中的只读验证结果，但不能发布交付；恢复后继续处理。取消后不能发布。所有节点和最终目标验证通过、交付消息处理完毕后，才写入 `completed`。

失败或证据不足会形成具体返工项，追加到同一个开放任务，保留工作目录、原始约束和执行历史；不重新创建任务来掩盖失败。每轮、每节点有独立返工回执，防止重启重复追加。默认每节点最多返工 2 次，可显式配置 0–10 次。达到上限为 `held`，仍表示未完成。

宿主按 DAG 调度，默认最多并行 2 个节点，可配置 1–10。下游只接收已验收前置节点的证据。上游返工后，已执行的下游进入等待依赖状态，待上游重新通过后自动刷新和重新验收；未经调度的外部交付物变动会使旧验收失效并要求处理。下游任务和验证会话都保留文档及传递引用的版本来源，支持原有来源撤回与上下文失效机制。结构化目标原始来源失效后隐藏节点指令，不能仅修改目标文字就复用旧图，需要新的明确授权目标。

## 分类恢复

| 情况 | 行为 |
| --- | --- |
| 验收不通过、证据不足 | 在返工额度内自动修复同一任务，再次核验 |
| 已确认没有未结副作用的临时网络/服务故障 | 持久化退避时间，默认从 2 分钟递增，最多自动恢复 5 次 |
| 配额/限流 | 从 30 分钟递增退避，最多自动恢复 5 次 |
| 权限、凭据、环境故障 | 保留原因并挂起，不能把重试当作修复 |
| 进程中断造成执行结果不确定 | 要求核对已发生的效果，避免自动重复有副作用的动作 |
| 验证器格式、验收项或证据引用错误 | 保持原验收规则，最多自动重做 2 次只读验证；持续失败则挂起，不重放 Worker 操作 |
| 旧任务已结束且没有可追踪的验收候选 | 明确挂起并说明需新授权目标，避免永久等待或伪造验收 |

任务、候选、验证轮、返工回执、发布回执及调度作业均存 SQLite。重启恢复不以模型记得聊天为前提。Router 原有原线程复用与持久化目标/要求仍保留。

## 边界

独立验证指新的会话、受限工具和宿主执行的验收规则，不等于另一个独立提供商，更不保证语义判断绝不出错。上述原始实测覆盖三种程序断言。现版本还支持本机 Worker 的 `xlsx_cell_equals`，可同时比对指定单元格与数值区域的合计。本机 XLSX、PDF、MP4 原件每份最多 32 MiB，按版本保存。独立验收使用小型观察记录。文本证据单文件上限 128 KiB，单轮证据上限 512 KiB。PDF 页面或视频内容仍需相应的内容验收。

本轮验证的是多阶段、跨进程恢复的任务流程，不能外推成数日连续运行、任意断电点或任意目标都必然完成。默认返工和恢复次数有限；不能完成会保留可解释的未完成状态，而非宣称成功。实际部署及生产实例验收仍须另行执行。新记录是附加存储，但不支持让旧宿主继续处理新增验收作业；部署回滚应停止宿主并恢复与旧版本匹配的备份，不能把“旧数据库可打开”视为状态机兼容证明。
