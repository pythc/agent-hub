# Webhook P1 实现审查与验收

基线：`2f695dd`（Agent board 0.1.3）。分支：`codex/webhook-p1-20261109`。

交付包括独立 HTTP 入口、签名与参数验证、持久 Inbox、人工批准的自动化模板、既有 Router Goal/Worker/独立验收/返工与重规划、事务领域事件、受控结果投影、持久回调和恢复 API。使用方法见 [WEBHOOKS.md](WEBHOOKS.md)，机器可读的真实验收结果见 [证据摘要](evidence/webhook-p1-20261109.json)。

## 自行 review 的重点与修复

1. **机器事件不是人类授权。** 事件保持 `human:false` 和独立 automation actor；通过持久 grant 回查真实人类 manager 的授权来源。模板、目标和验收标准不得由 payload 修改。任务调用、恢复及回调均复核权限。新数据不自动激活 Agent 记忆。
2. **人工暂停/恢复不丢身份。** 人工 manager 可在原 entry 查看、暂停、恢复和取消自动化目标；恢复保留机器触发锚点与原合同，不能把目标换成人类身份绕过已撤销 grant。已排队 Worker 在暂停后不执行；完成后的机器 Router 只允许检查原结果，不能再创建目标或更改 Worker 配置。
3. **收件与执行一致性。** ACK 前持久化；规范化业务身份唯一；并发与跨端点轮换仍去重；同 ID 改正文冲突。Inbox 与 Goal 创建/关联同事务；最后关联写失败时清除已回滚的 Goal/trigger 指针，不向调用方返回虚构目标。按 grant 公平取件，避免一个并发已满的队列挡住其他授权。
4. **只从独立验收生成成功回调。** 领域事件与状态变化同事务；完成事件另查当前整体验收证据。测试注入事件 Outbox 写失败后，目标不误报完成，恢复存储并经人工 resume 可继续提交原结果，不重跑已验收 Worker。
5. **投递与执行解耦。** 稳定 event/delivery ID、冻结正文/目标、按尝试重新签名；丢失响应和 503 仅重投。401/403 held、永久错误 dead、预算耗尽 dead，人工恢复仍复核原授权。旧 `MessageSource.replyUrl` 不确定副作用语义保持不变。
6. **回调边界。** 只公开批准的验收文件；完整内容限额、SHA-256 与省略原因明确，不输出私有日志/记忆。检查 DNS 全部结果并固定连接 IP；解析后再次检查授权；禁止重定向和私网，使用精确子网判断，避免误拦截整个正常 IPv6 公网段。
7. **升级/回滚。** 创建授权启用 schema 8；修复记忆模块每次启动写回 schema 7 的兼容问题；受控配置恢复与备份工具识别 schema 8。旧备份不得覆盖已经推进的 Inbox、授权撤销、领域事件或回调尝试。用实际旧版 Store 源码验证其拒绝 schema 8，而非仅断言一个版本数字。

未修改 DeepSeek/WeKnora vendor 代码，没有新增第三方依赖，也没有引入第二套任务调度器。

## 固定实现的真实任务验收

`examples/webhook-acceptance.ts` 使用真实 Codex Router、Worker 和全新会话的独立 verifier，以及实际 HTTP 收发。源数据为 30 条记录、18 个唯一 ID，X/Y 汇总为 594/657，总额 1251；三个阶段依赖顺序为清洗、汇总、报告。

| 场景 | 实际观察 |
| --- | --- |
| 重复事件 | 各进程通过 HTTP 并发重投同一事件，最终 1 receipt、1 Goal、3 个任务 |
| 收件后重启 | 第一次 SIGKILL 在 ACK 后、Goal 创建前；重启后继续处理原收件 |
| 错误 ready | 首次清洗把 K01.amount 写成 999，并报告 ready；确定性验收拒绝，未释放结果或发成功回调 |
| 自动返工与恢复 | 第二次 SIGKILL 在错误验收后；重启后原任务返工一次，原合同保持不变 |
| 整体独立验收 | verifier 实际读取证据，全部原始标准与整体约束通过 |
| 投递中断 | 接收端持久接受第一次回调但不回应，第三次 SIGKILL 中断 sending |
| 回调重试 | 同 delivery ID 和正文经历未回应、503、204 三次尝试；接收端业务效果 1 次 |
| 任务不重跑 | 回调恢复期间 Worker 执行次数未增加 |
| 输出权限 | 只交付批准的 summary.json、report.md，内容与已验收快照一致 |
| 版本一致 | 四个宿主启动时的所有变更运行源文件 SHA-256 相同，并与交付文件逐项一致；最终数据库版本 8 |

测试中的错误是明确安排的故障注入，不是自然出现的错误。真实 Worker 的文字回复披露了这个故障，但状态仍为 `ready`；本轮证明宿主拒绝“不满足标准的 ready”，没有冒称模型隐瞒了错误。另有自动化回归明确注入“全部正确、总额 42”的错误报告并验证它被拦截。

先前探索性真实运行保留但不计入这次固定实现验收：一轮在测试过程中有代码变化，一轮被模型 verifier 的 300 秒调用期限中止并保持 held，未生成成功回调。最终证据摘要只来自最后一轮固定实现的完整通过结果。

## 交付边界

这是 P1 通用协议与管理 API。公网代理/TLS 部署、平台原生 Webhook 签名适配、完整可视化管理页、上游漏事件对账、自动归档保留期不在本次范围。回调是有尝试预算的 at-least-once，接收端必须持久去重。外部模型不可用或证据不足时，目标仍可能 held，不能把持续调度表述为无条件成功。

验证使用隔离 state、workspace、随机测试密钥和 loopback 接收端，未切换本机飞书运行实例，未向飞书群发测试消息。
