# Router 主动管理第一批

## 使用入口

在运行本版本的宿主中，打开「Router 与记忆」→「职责与定时任务」（`/router-proactive`）。先创建管理范围并绑定入口，再设置职责与消息节奏。默认不改变既有消息入口；开启范围的批次研判后，连续消息进入持久批次。职责支持多个入口、关闭 / 只观察 / 自动处理；全局 `acceptMode` 仍是推断执行上限。

管理页支持保存职责、编辑计划、暂停/恢复、立即运行、停止某次运行，以及查看介入理由、执行状态和交付状态。普通群成员继续经由既有准入规则提出任务；Worker 不直接向群发送结果。模型中的 `router_manage` 工具使用同一服务，写操作只允许当前明确授权的管理者；HTTP/MCP 是已认证操作员控制面。

## 运行语义

- 聚合键包含管理范围、入口、话题、成员、授权强度和规则版本。默认窗口 1.5 秒、最长 5 秒；主动介入间隔默认 60 秒。明确请求不受主动介入间隔限制。研判时到达的新消息进入下一批。
- 介入结果为新任务、续接、忽略、澄清或明确停止。模型只能从实际可访问的同话题任务或明确提及的任务中选择续接目标，语义相似不构成合并依据。推断输入必须逐条评估书面职责，观察模式不执行。
- `attach` 直接调用现有 Worker 的续接入口，保持 Ticket、Worker、模型后端和原生线程。不会再启动一个自由协调回合来决定是否重建任务。原任务的请求/结果权限及发起人或管理者边界继续有效；职责不自动授予对任意成员任务的修改权。
- 批次的全部输入、研判读过的任务版本、范围及入口都是执行依赖。职责变化、撤回、改绑、任务转交或内容变化会阻止旧决定继续执行，控制台保留失败原因。转交任务不会把旧 Router 的职责带入新管理范围。
- 实际任务、Assignment、工具效果回执和 outbox 继续作为状态事实来源。Router 只是选择动作与汇总结果；计划结束、任务结束和消息交付分别显示。

## 定时任务

每份计划保存名称、来源授权、任务正文、运行方式、周期、时区、起止时间及通知方式。创建计划须引用一条当前有效、由该范围管理者发出的明确真人输入；Router 工具只能引用本轮输入，操作员不能借私有消息冒充成员。

支持单次、固定间隔（至少 60 秒）、每日、每周。时间戳需带偏移，日历计划使用 IANA 时区；周日为 0。不存在的夏令时时刻跳过，重复时刻每天只取第一次。不实现完整 cron / RFC5545。

「每次独立执行」产生独立的话题与运行记录，使用当前范围 Router 配置、来源工作环境及获准 Worker。「跟进已有任务」绑定原任务，保留其执行环境和原生线程；已完成或人工停止的任务会跳过，需要新的真人请求才能重开。定时来源标记为 `human:false`，通过宿主保存的计划回执获得常驻授权，不伪造平台真人事件。

暂停仅影响后续或尚未派发的触发；已开始的运行保留当时的任务正文。停止当前运行是另一操作，会撤销本次输出并停止其未结束的任务。来源授权失效则立即阻止后续工具和交付。计划不能递归创建计划或重配 Worker。

主机必须在线且宿主在运行。停机积压合并为最近一个到期时刻；每次发生具有稳定身份，不在重启时补跑整段积压。上次任务或不确定工具效果未收束时跳过下一次，Router 出错也不能绕过这个检查。失败运行如仍有任务可单独停止；不确定外部效果仍须按现有核对机制处理。

通知支持每次报告、有需关注的发现时报告、静默记录。是否存在需关注的发现由 Router 根据任务证据判断；静默在宿主外发层强制执行。结果送回授权来源入口，不自动扩大跨群共享。UI 的执行结束不等于业务目标达成，应同时查看实际任务和交付状态。

## 接口

- `GET /router-proactive/state?scopeId=...`：操作员读取当前配置、最近 100 次运行及介入。
- `POST /router-proactive`、MCP `router_manage`：`list`、`settings.put`、`duty.put`、`schedule.put`、`schedule.pause`、`schedule.resume`、`schedule.run`、`run.cancel`。
- 写操作需 `scopeId`、稳定的 `operationId` 和当前 `expectedRevision`。并发版本冲突必须刷新后处理。重复请求返回原回执。
- 结构化契约见 `src/router-proactive.ts` 的 `proactiveCommandSchema` 和 `src/schedule-time.ts` 的 `timingSchema`。Router 工具列表只返回当前入口内容；操作员视图排除私有入口正文。

例：

```json
{
  "action": "schedule.put",
  "scopeId": "team",
  "operationId": "create-daily-check-1",
  "expectedRevision": 0,
  "schedule": {
    "id": "daily-check",
    "name": "每日构建检查",
    "triggerId": "当前有效的管理者输入",
    "prompt": "检查授权项目的构建状态，汇总仍未处理的失败；不修改代码。",
    "mode": "standalone",
    "notification": "findings",
    "timing": {
      "kind": "weekly",
      "timezone": "Asia/Shanghai",
      "startAt": "2026-11-09T09:00:00+08:00",
      "time": "09:00",
      "weekdays": [1, 2, 3, 4, 5]
    }
  }
}
```

## 持久化、升级与边界

职责、节奏、计划、运行、批次、输入依赖和命令回执存入现有 SQLite records/jobs，与入队事务一致。新增记录类型进入迁移识别表。普通历史正文删除会删除关联计划正文并使其授权失效；职责和节奏是独立控制配置，不伪装成普通记忆删除。尚未清理完的效果记录不会被当成新执行许可。

本轮没有对正式部署执行迁移或替换。回退至不理解这些记录/作业的旧程序前，必须暂停计划、排空或明确停止执行、核对不确定效果，再使用相匹配的程序和备份；不能声称替换源码会回滚外部效果。

本批提供职责、批次、续接、介入与持久定时来源。仍不是全量 dots：没有开放式长期目标自主拆分、无限期跨任务催办或跨组织调度，也不提供离线云执行。企业服务接入继续由现有适配器承担传输与身份，主动管理逻辑不依赖飞书协议。
