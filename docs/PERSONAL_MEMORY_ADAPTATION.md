# 在任务中学习协作偏好

这次改造把个性化接到实际任务、记忆生命周期与控制面。Router 和 Worker 继续默认由一名 Worker 完整负责同一任务；后台记忆整理不增加任务交接。

## 行为与范围

- 冷启动从第一项任务开始，读取已授权的项目资料与约定。只为会改变下一步决策、且现有上下文无法回答的信息提一个问题，不要求先填写画像。
- 新增 `adaptive`（在任务中学习）模式，兼容 `explicit_only` 与 `auto`。升级及记忆界面改版都不自动修改已有实例的学习策略；日常界面不再要求用户配置学习模式。
- 普通工作偏好可自动启用。`learning.inferred` 保留明示与推断的区别，`condition` 描述适用条件，自动抽取的 `quote` 保留来源引文。推断作为可修正的暂定偏好；它不能自动替换明示或人工确认的偏好。
- 临时偏好记录讨论标识，只在同一讨论提供给模型。它与长期偏好共存，不替换长期版本。其他语义条件由模型结合当前任务判断，不宣称宿主能确定性理解全部条件。
- 明确的长期偏好修正复用现有版本替换事务，旧版本停止使用，来源和历史保留。其他事实、删除及整理合并仍走候选确认。
- 已完成且最终独立验收通过的目标，可把验收记录中的方法与失败教训加入原有后台观察队列。只在 adaptive 模式处理，复用取消、重启恢复、来源、遗忘与日预算；不采用 Worker 单方面的成功声明作为验收。
- 从执行记录归纳的方法保留适用条件和引文，原始请求撤销时对应派生证据与经验一起失效。模型的归纳仍需实测，不能把历史成功当成当前任务的成功证明。
- 每轮保持少量常驻偏好与相关记忆，详细记录按需检索。提示词预览与执行使用相同的个性化指引。

## 控制面

记忆唯一入口是“设置 → 记忆”（`/configure#advanced/memory`），与宿主状态等设置共用导航、主题和语言。会话侧栏、共享指令和旧 Router 管理页不再提供独立记忆入口或管理面板。

界面汇总既有公共入口当前获准管理的已生效记忆，不要求选择消息或配置入口。每条只提供**修改、删除**：修改只编辑正文并保留来源、适用条件和范围；删除沿用持久遗忘语义，支持提交前取消。候选建议不混入已保存列表，也不会因隐藏确认界面而自动通过。

学习开关、候选确认、来源历史、使用记录以及技术参数不再出现在日常界面。既有记忆策略和后台学习流程保持不变；维护 API 仍保留。未绑定范围的新会话仍不会自动启用长期记忆，打开设置也不会创建全局范围。

旧 `/memory-workbench` 和 `/configure#prompts/memory` 地址转到设置。已保存的会话“记忆”标签会移除，其他浏览器、文件标签及会话草稿保留。

## 升级与回退

记忆格式标记从 2 升至 3，原事实 ID、状态和学习策略保持不变。旧程序会拒绝读取格式 3，避免忽略临时适用范围等新增语义。升级前停机备份完整状态；回退使用升级前备份与对应旧程序，不手工把格式标记改回 2。升级后的任务进度与外部效果仍按现有备份恢复约束处理。

## 验证

定向测试覆盖明示偏好生效、跨会话修正、临时例外、推断与明示冲突、遗忘、来源删除、验收经验及旧策略迁移。浏览器脚本验证真实 HTTP/SQLite 的设置保存、适用条件修改、协作预览和移动布局。

```sh
npm run check
node --import tsx examples/personal-memory-acceptance.ts /tmp/roppo-personal-memory-fresh
MEMORY_BROWSER_DIR=/tmp/roppo-memory-browser node --import tsx examples/agent-memory-browser.ts
# 另一个终端；需要 Playwright Python 与 Chromium。
MEMORY_BROWSER_DIR=/tmp/roppo-memory-browser python tests/browser/agent-memory.py
```

原生验收使用真实模型与隔离的本地合成仓库：连续偏好学习、临时例外、长期修正、重启后的实际报告顺序，再执行不指定分工的 Unicode 截断 Bug 修复。它不发送飞书消息，也不代表生产部署验收。
