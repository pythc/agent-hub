# Router 主动管理第一批：实现前 review

2026-11-07。按用户要求，先静态 review，再实现、diff review、测试；此文件初次写入时尚未运行本轮测试。保留当前工作树全部既有修改，基线在 `/tmp/agenthub-proactive-baseline-20261107`，证据目录 `validation/router-proactive-20261107`。

## 已核对的现状

- `RouterIngress.admit` 对每个输入立即排队，不能聚合连续消息；同讨论的 Router 执行虽串行，研判仍逐条发生。
- `assessRouterInput` 接受 attach，但 `decide` 只转为 accepted 并再启动 Router，未形成绑定原任务的续接动作。
- 规则目前只有全局 config.rules/acceptMode，没有按管理范围及入口管理的常驻职责。
- jobs 支持持久队列和恢复，但没有日历调度、计划状态、每次触发的独立回执，也没有定时授权来源。
- 核心 Ticket/Assignment、任务入口许可、工具效果回执及上下文屏障已经存在，不能另外制造一个“任务完成”状态真源。

## 本批实现契约

1. 职责属于版本化控制配置；管理范围/入口限定，默认 observe。配置全局 off/observe 仍是推断执行上限；普通记忆不能变更职责。Router 工具仅让当前明确授权的管理者修改，操作员 HTTP 有独立控制面。
2. 聚合键包括管理范围、入口、话题、actor、授权强度和规则版本，不把不同身份/受众/授权拼成一个请求。有短聚合窗口及最大等待；运行中新增消息进入下批。记录全部输入与决策，重复事件不重复执行。
3. 明确指向已有任务或同话题唯一可续接任务可直接接续；多任务歧义要澄清。语义相似本身不能合并任务。追加前仍检查原任务权限、当前上下文、人工停止和效果状态，Worker 只向 Router 交付。
4. 时间条件由宿主内部定时来源生成，走相同授权、Router 和 Worker 路径；不得伪造真人消息。保存计划、版本、时区、下次时间、每次运行回执和结果状态。支持单次、固定间隔、每日/每周；不宣称支持完整 RFC5545/cron。
5. 独立运行与既有任务跟进分开。跟进不重新建同名任务，不自动重开人工停止或已结束任务。过期触发合并至最近一次，不在重启时补跑整个积压；同计划不重叠。暂停计划仅停止后续触发，停止当前运行是另一个明确动作。
6. 时区使用 IANA；夏令时不存在的当地时刻跳过，重复时刻每日只执行一次。主机离线时不会执行；恢复按明示补发策略处理。
7. 每次调用、工具和外发检查当前授权。新职责/计划不扩大 Worker 工具权限或环境；已发生效果保留回执，重试不得换 ID 重做。运行结束与交付成功分开记录。
8. 提供可用的管理接口、Router 工具和管理页：职责、计划、暂停/恢复、立即运行、每次运行与介入记录。计划只在配置后生效，不改正式部署。

## 测试前检查清单

- 普通成员、推断事件、模型记忆、伪造定时元数据均不能获得管理权。
- 聚合/研判期间撤回、规则修改、群改绑、并发输入不会采用旧决定。
- 同任务同线程接续、多人/多群隔离、歧义、人工停止、重复触发各有确定性断言。
- 调度测试注入时钟；覆盖跨午夜、时区、DST、一次性/周期、停机积压、暂停与当前运行停止、重启幂等、失败和实际交付状态。
- 历史清理、备份恢复、迁移记录目录同步检查新增类型，不删除职责配置冒充普通记忆清理。
- 新功能回归后跑全量；浏览器验证真实操作。真实模型验收必须保存协议和实际任务/线程，不用替身冒充。

## 首轮实现后、执行测试前的静态 review

已逐项核对入口 → 批次 → 模型研判 → Worker 管理 → Router 汇总 → outbox，以及时间计算 → 持久触发 → 当前授权 → 运行结算。静态检查先修正了：

- 单次计划到期不能被当成用户暂停，阻断自己已创建的运行。
- 批次全部原始输入必须成为持续授权依赖，不能只验证最后一条消息。
- 排队期间新消息或上一轮介入改变截止时间时，重排批次，防止突破聚合窗口和冷却间隔。
- Worker 已结束但结果尚未汇总时，计划仍在运行，不允许新一轮重叠。
- 模型工具读取计划只返回当前入口；操作员不能借私有消息身份管理计划。
- 历史正文删除后新增记录须可安全读取，且计划不能通过旧授权重新生效；职责配置按独立控制配置保留。
- 新记录类型加入迁移识别表，vendor 无改动。

以上完成后才开始类型检查和测试。确定性测试使用可注入调度时钟；模型替身只用于回归逻辑，不计为真实模型验收。

## 最终自行 review

再次沿实际状态链检查并补齐以下边界：

1. 旧单条 admission 的 attach 也绑定原任务，避免只有新批次路径修复了伪续接。
2. Router 失败后遗留任务仍阻止计划重叠；从实际 Worker assignment/task-routing 恢复跟踪，覆盖任务提交后、运行索引写入前崩溃。失败且有残留任务的运行仍可停止。
3. 停止本次运行主动取消 Router 模型请求，同时保留未来计划；晚到的模型文本不能交付。
4. 消息批次全部输入持续参与授权检查；研判读取的每个任务都写入上下文依赖，覆盖多任务话题中的任务正文变更。
5. 职责按实际 Router 归属筛选，任务转交后不能继续携带旧范围职责。修改职责或计划回执不能跨入口重放。
6. 历史删除、私有入口、模型递归创建计划、完整协议预算、运行中规则修改均有回归断言。
7. 浏览器实际操作保存节奏、创建职责与计划、暂停、恢复、立即运行并读取真实运行/交付状态；修复窄屏表格挤压，检查键盘和控制台。

测试中聚合范围最初只取最后一条消息，已修复为整批显式请求并保留每条授权依赖。两个回归替身也修正为符合核心语义：waiting 不等于已向 Router 交付，已结束任务调用 stop 不会重新改变旧结束原因。

全量测试曾出现既有 CLI 子进程启动超过 3/5 秒的失败，保留了失败日志，没有跳过断言。飞书错误订阅测试改用 `/bin/sh` 输出同一多行 JSON 和退出码 2，仍真实启动七个消费进程并验证全部诊断；去掉七个仅用于打印 JSON 的 Node 冷启动。最终全量使用 2 个测试进程、15 秒测试/清理上限，保留实际协议与结果断言。普通 API、连接器、备份/迁移、历史删除及原型核心回归均纳入全量。

本轮不改正式部署配置、不重启正式服务；原有平台生命周期事件订阅验收仍按用户指示暂缓。本轮真实模型验证使用独立本地入口，不能称为飞书生产验收。
