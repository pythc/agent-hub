# O41a: current-host local diagnostics

The Current environment page (`#environment`) belongs to the selected workspace transport. It exposes operator-only `GET /api/local-diagnostics` and explicit `POST /api/local-diagnostics/probe` with the current settings revision. It does not select, migrate to, or inspect another machine. Both endpoints reject nonempty query strings with `local_diagnostics_query_invalid`; workspace/source selectors cannot redirect a local check.

GET only reads current platform, Node version, configured sandbox driver and volatile check evidence. It starts no process, changes no settings and makes no provider/account/source call. POST reuses `probeSandbox`: a newly created temporary directory, fixed `printf`/`echo` command, read-only workspace, network disabled, minimal environment, 10-second child execution timeout, and SIGKILL on timeout. The existing driver builds its normal isolation policy; there is no unrestricted fallback. This checks startup, not comprehensive sandbox security, task permission or arbitrary commands. Disabled is not passed. Missing executable, unsupported platform, namespace denial and timeout return a safe failure code, never raw stderr, environment values or credential paths.

One probe runs at a time per service. Duplicate concurrent requests receive `diagnostic_busy`. Start and end validate operator authority; captured Runtime identity and settings revision must still match before publishing evidence. Checks are volatile and disappear after replacement or configuration changes. They are not persisted as authorization or global capability grants. Closing the page or losing its workspace stops UI consumption, not the already-started fixed local process: it finishes within its existing bounded execution window and cleans only its own temporary directory. No browser profile or user worktree is used.

Browser startup is explicitly **unsupported here**. Existing browser doctor APIs create a temporary profile but do not provide the strict no-network and daemon-cleanup guarantees needed for this diagnostic. The page does not invoke them, navigate a site, use an existing profile or verify login. Browser configuration, a healthy host and a sandbox startup pass do not prove website access, model availability, publication authority or recipient delivery.

Validation includes real Runtime HTTP authentication/origin checks, revision and Runtime replacement races, safe failure/retry, no GET database writes, frontend lifecycle and transport fencing. Unit probe injections are simulated results, not environment verification. On the development Linux container the real bubblewrap probe returned namespace/proc-policy denial; no setting was changed or fallback attempted. O41a's broader environment selection and O41b cross-machine work remain out of scope.

## Current-runtime capability descriptor

The same GET now includes a versioned `environment` descriptor: one current-host reference, observation time, configured local entry workspace modes, and capability-specific eligibility. The opaque reference is stable only for the current Runtime instance, changes after replacement, and is not a machine registry ID or authorization token. No source IDs, paths, browser profiles, credentials, or account names are returned. Workspace modes come from enabled local entries with an operator configured; they are not proof of actual per-task directory access. Sandbox startup evidence remains tied to the same Runtime and settings revision.

The UI's explicit sandbox check stays on the captured workspace transport and submits its observed environment reference and settings revision. A stale reference is rejected before the probe even when the replacement has an identical revision; mismatched results are not shown. Older callers may omit the reference and retain their prior local-only behavior; no request can select another host. The user's visible choices do not include a disabled sandbox check or a browser publishing target: browser login identity is unavailable or unverified here regardless of sandbox evidence. Disconnects do not trigger any fallback.

This adds an advisory current-environment binding and eligibility view only. It introduces no dispatch, browser login probes, device discovery, cross-machine migration, or delegation activation. O41b remains unimplemented.
