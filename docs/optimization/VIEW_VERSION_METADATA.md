# O32: retained View version metadata

`GET /api/workspace-views/:id/versions/:digest` resolves a fixed manifest digest to verified package metadata: `reference`, `label`, `packageVersion` and whether it is `current`. It uses the existing operator authentication boundary and returns no executable code, runtime data, capabilities or filesystem paths. The response is not cached.

The current enabled mount remains the authority. A removed, disabled, damaged or mismatched current mount denies historical metadata too. The current digest can resolve from its configured location; older digests must exist in this runtime's own `stateDir/plugins/objects`. Resolution verifies the requested manifest digest, code checksum and manifest ID, and refuses symlink directories. Missing or cleaned objects return unavailable. There is no lookup in another workspace, fallback digest or automatic installation. Previously staged but never activated packages can be resolved if they remain in that private store and have the same currently enabled ID; this is retention metadata, not activation history.

Historical bundle and runtime requests remain unavailable. Existing bundle/runtime routes still require the currently enabled digest, and runtime still requires its current capability. This slice adds no UI entry, history listing, registry migration, publication state or execution permission. Existing UI wording about unsupported historical opening remains accurate.

Automated tests use real package builds, isolated runtimes and HTTP requests to cover upgrade/rollback, fixed identity, missing/tampered objects, ID mismatch, revocation, workspace isolation, directory symlinks, authentication, method/query validation and rejection of historical execution. Full-suite baseline comparison and exact-head remote checks/review are recorded in the PR. Real IM, browser visual/mobile/keyboard/animation acceptance remain deferred and unverified.
