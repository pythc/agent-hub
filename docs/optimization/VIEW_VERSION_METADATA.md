# O32: retained View version metadata

`GET /api/workspace-views/:id/versions/:digest` resolves a fixed manifest digest to verified package metadata: `reference`, `label`, `packageVersion` and whether it is `current`. It uses the existing operator authentication boundary and returns no executable code, runtime data, capabilities or filesystem paths. The response is not cached.

The current enabled mount remains the authority. A removed, disabled, damaged or mismatched current mount denies historical metadata too. The current digest can resolve from its configured location; older digests must exist in this runtime's own `stateDir/plugins/objects`. Resolution verifies the requested manifest digest, code checksum and manifest ID, and refuses symlink directories. Missing or cleaned objects return unavailable. There is no lookup in another workspace, fallback digest or automatic installation. Previously staged but never activated packages can be resolved if they remain in that private store and have the same currently enabled ID; this is retention metadata, not activation history.

Historical bundle and runtime requests remain unavailable. Existing bundle/runtime routes still require the currently enabled digest, and runtime still requires its current capability. The fixed metadata UI entry is `/configure?workspace=<id>#artifact-view-version/<view-id>/<manifest-digest>` (omit the workspace query for standalone mode). The artifact catalog links to the digest captured on that page, separately from the current executable View entry. The metadata page uses the existing workspace lease, rejects mismatched identities and malformed responses, cancels stale reads on route/workspace changes, and supports refresh/retry. It never requests bundles or runtime data and does not create an iframe. Availability/current status reflects the last successful read, not a permanent grant. There is no history listing, registry migration, publication state or execution permission. Retain a fixed URL to inspect the same retained digest after an upgrade; removed/cleaned versions remain unavailable.

UI hook tests cover captured-workspace routing, fixed identity, refresh/retry, late responses, invalid route/payloads and lease invalidation. Real browser visuals and keyboard/mobile acceptance are still unverified.

Automated tests use real package builds, isolated runtimes and HTTP requests to cover upgrade/rollback, fixed identity, missing/tampered objects, ID mismatch, revocation, workspace isolation, directory symlinks, authentication, method/query validation and rejection of historical execution.
