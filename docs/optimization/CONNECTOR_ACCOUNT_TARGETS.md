# O17 account-qualified directory checks

The Connections page lists each configured instance separately, including its source ID and a display-only fingerprint of a pinned account. Choose the correct Slack/Linear instance and one channel/team in its member-directory selector. Same-named instances or entries still have different source identifiers and/or native target IDs. There is no selected default and there is no fallback to a different connection.

For a targeted check, the host resolves an opaque target key against the exact source, pinned account revision and configured listeners. Where Router management scopes are active, it also requires an active matching entry and binds the key to its revision and tenant epoch. Checks run only on the chosen directory, remain distinct from older whole-connection checks, and are discarded if authorization, the account or configuration changes mid-check. The existing whole-connection capability route remains available for older clients; the new selector does not call that route for these providers. Neither form grants access or sends any messages. Pin an account with the existing Router management identity/bind flow.

Remote operator checks have a durable six-starts-per-minute window per configured source and pinned-account namespace (local settings checks are free, and duplicate request IDs do not spend again). There is one in-flight remote check per source; a client-side/diagnostic timeout does not release that source's workload lease before the underlying operation settles. A separate whole-host concurrency ceiling still protects the host. The window counts diagnostic requests, not individual HTTP requests or any provider's plan allowance. Background source-health and an observed provider retry deadline, if saved, are reported separately. Slack/Linear keep provider rate-limit cooldown on the same instance and do not select another connection when throttled. A pre-start provider cooldown may be process-local until the adapter has a state context.

A verified account mismatch quarantines the old connection rather than granting a different identity its authority. Create a new separately verified source for an intentional account change. This change does not add OAuth setup, automatic destination discovery, provider billing telemetry or a cross-channel write selector. Real two-account, callback and provider acceptance remains part of G05; no fixture or check here proves those platform behaviors.
