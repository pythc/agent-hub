## 真实模型验收

使用 `examples/router-proactive-smoke.ts`，独立本地来源和状态目录，不向飞书生产群发送消息。Router 为 `gpt-6.1-terra / medium`，四个 Worker 为 `gpt-6.1-sol / high`。

验收流程：两条本地操作员验收消息合成一个批次（脚本注入，非飞书真人事件） → 四个 Worker 分别计算 1+1、2+2、3+3、4+4 → Router 汇总 → 明确引用原 2+2 任务续接并复核 → 独立定时来源触发 Router 计算 6+6。

最终版本证据记录在 `native-final/evidence.json`；它包含实际模型调用、任务、Worker 原生线程、介入决定、定时来源、运行状态、交付和执行代码哈希。原生历史核对记录在 `native-final/native-history-verification.json`，用于区分请求参数与实际原生线程参数。最终机器核验汇总见 `completion.json`。本次真实检查全部通过：4 个 Worker 持久线程、4 个 Router 持久线程均从原生历史核对模型与思考强度；2 次 ephemeral 研判按设计不保留原生线程历史，仅以实际调用及配置回执核验。执行时保存的 7 个关键源码哈希与最终实现完全一致。

验收明确区分：用户输入只进入 Router；Worker 结果的出箱地址为内部 Router inbox；对外消息均由 Router 生成。复核保留四个原任务和四个原生线程，只再次激活负责 2+2 的 Worker。定时输入为 `human:false`，无伪造平台真人证明，独立产生运行回执。
