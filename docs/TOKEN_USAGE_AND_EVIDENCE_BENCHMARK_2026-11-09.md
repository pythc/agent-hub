# Token 统计与原件证据交接：实现和实测记录

2026-11-09。本轮在隔离分支 `codex/roppo-token-evidence-20261109` 完成实现和试验，未部署、推送或发布插件。现有实例的账户、权限、配置与任务数据未由本轮修改。

两轮普通任务的 A/B 两组均完成原有独立验收，合计已报告 token 从 **1,049,315 降至 332,539（−68.3%）**，未缓存输入从 **234,286 降至 173,184（−26.1%）**。平均端到端耗时从 **268.8 秒降至 151.1 秒（−43.8%）**。这是两对成功样本的描述统计；每对耗时降幅分别为 15.1% 和 61.7%，样本不足以给出稳定的生产加速承诺。

**统计口径与看板**

已接入 Router、Worker、子代理、独立验收、重规划、独立方案复核、记忆处理、辅助判断和独立监督巡检。用量来自后端返回的数值字段，保留输入、缓存输入、写缓存、输出、推理输出和总量；缺报保持未知，明确返回的零值才显示零。缓存属于输入，推理属于输出，均不重复相加。总量与金额不同，本轮没有把订阅用量换算成账单。

按 provider step 保存快照，同 ID 更新进行替换，重试另记；失败和中断前已返回的用量保留。原生线程的累计计数用于识别更新，累计时使用该步的计数，避免每次把整段历史重复相加。API 非流式、Responses SSE、Chat SSE 与 Anthropic SSE 均接入；旧插件缺少回调时记为未知。连接探测不属于这份团队业务调用统计。

看板插件 **Agent board 0.1.4** 在“监听与用量”提供团队合计、用途分组、来源筛选、有用量／未知／部分用量覆盖和统计起点。原有辅助判断面板仍使用它原有的全部来源、最近记录口径。插件只获得数字汇总，不获得提示词、原生历史、工具参数或凭据；旧宿主显示尚未提供统计。

监督进程在自己的已有数据库保存数值、调用 ID、来源 ID、用途、时间、状态及 backend/model 元信息，不新增目标正文、证据或判断的持久副本。宿主只读该库的用量记录；读取失败时看板明确提示合计可能不完整，不干扰巡检、判断或恢复。升级前的用量不伪造回填；旧监督记录也不能推算出当时的 token。

现有历史正文清理规则保持：宿主清理删除了关联用量明细后，该调用转为未知；晚到的回调不能恢复这些明细。监督库的数值元数据独立保留，不随宿主正文清理清空；它们没有目标、证据或判断正文可以恢复。

**原件交接与验收边界**

进入全新验收／重规划会话时，宿主把预算内的完整原件随初始输入交给模型，减少逐页取证往返。只选择完整的 `{id, content}`，上限为 32,768 字节，并受既有 scope／API 上下文预算约束。较大原件继续通过原有有界、按 Unicode 位置连续无缺口的分页读取。

交付确认发生在模型返回且宿主重新验证快照和权限之后。仍要求逐项决定原标准、引用实际交付的证据、检查全部声明的文件／文档及要求的执行记录；重规划仍需独立复核。原目标、预期值、授权、人工停止、能力限制、修复／重规划次数和任务侧网络政策均保持原来的检查。完整交付及引用覆盖不等于能够证明模型逐字注意了全部内容。

每对的目标、授权、验收原文、配置和原始输入哈希均一致；每个 tick 检查授权与标准未变；成功需完成原标准且没有活动执行或待运行作业。每次结果均与对应原生线程最终累计用量及 provider step 数独立对账。首对没有自动保存逐文件源码哈希，后续三对保存了这些哈希；没有事后补写首对的哈希。

**尚未解决的实际限制**

重规划之后，优化组最大的单份执行证据约 49,710 字节，序列化为内联项约 54,867 字节，超过当前内联上限。剩余分页、执行记录和会话历史仍可能撑满原有 256,000 字节预算。这次没有提高预算、删除失败证据、缩减验收标准或用摘要替代原件。修复场景改善和重规划场景仍失败，只能支持有限范围的结论；不能宣称所有 A2A 场景已优化成功。
