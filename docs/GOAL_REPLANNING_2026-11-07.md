# 失败证据驱动的自主重规划

日期：2026-11-07。本文对应隔离工作树中的实现，未部署到日常 AgentHub 服务。最终真实运行与审查结果见下方验证记录。

## 行为与边界

结构化目标保留不可变合同：原始目标、所有验收项、原始用户触发事件及摘要、授权 Mandate，以及初始 Worker/backend 允许集合。Router 可以改变完成目标的方法，不能修改合同。即使直接调用目标更新接口，也不能替换这些字段；改变目标需要新建明确授权的目标。

当验收返工额度耗尽，或 Worker 报告已确认的方案/工具缺失问题，宿主等待执行和通知稳定后，冻结失败报告、实际命令及退出状态、文件/文档内容和验收结果。Router 配置的模型在只读规划会话中提出执行图变更，另一个只读会话独立审核。两个会话都必须通过 `goal_evidence` 读完并引用全部保留证据；文件、文档和报告不能成为新授权。

```mermaid
flowchart LR
  A[保留失败与实际执行证据] --> B[提出替代方法和执行图]
  B --> C[程序校验合同、范围与依赖]
  C --> D[独立审查方案]
  D --> E[事务保存执行图新版本]
  E --> F[调度中间步骤并独立验收]
  F --> G[原任务原线程继续]
  G --> H[按原始标准整体验收]
```

程序约束包括：

- 只修改失败节点及其下游的实施说明和依赖。保留原节点、任务 ID、Worker、原验收项归属和失败历史。
- 新增步骤必须声明原父任务、支持的原验收项和工作区内输出，并成为父任务的前置依赖。禁止孤立扩展、循环、重复节点、越权 Worker/backend 和越界输出路径。
- 中间步骤有独立内部验收，但不能替代或删除原始验收。整体验收还会读取中间产物及实际执行记录。
- 下游节点及整体验收均按验收项所属节点的依赖闭包关联宿主台账和材料，核对跨阶段执行声明；上游材料可支持相应语义验收，无依赖关系的旁支材料不会被关联。程序验收项的文件归属保持不变，避免同名文件混用。上游产物在审查期间变化会使下游验收失效，不能借用过期的“已通过”。
- 重新执行前清除受影响的旧验收结论，等待新前置依赖通过；沿用原任务和原 Worker 会话。仅在独立批准的重规划路径中，宿主将已确认的实施阻塞转回等待执行，避免核心对自动输入的阻塞保护使新方案永远无法启动。
- 权限失效、凭据问题、不确定副作用、人工停止、来源撤销或过期方案均不能靠重规划绕过。模型输出与应用之间多次核对目标版本、授权及证据摘要。

默认允许 2 次成功应用的重规划，可在明确的人类输入下设置为 0–5。每轮最多增加 20 个节点，总数最多 100；同一方案下的返工次数仍受 `maxRepairs` 限制。额度用尽、方案被拒绝或证据不足时保留未完成状态，不报告成功。

规划和独立审查输入明确给出每个节点的同方案返工额度、已使用/允许的成功重规划次数。`maxRepairs=0` 表示不重复当前实现，不等于禁止在 `maxReplans` 允许范围内提出替代方案；因质量问题而 held 也不等于人工停止。已结束任务、人工停止和暂停仍由宿主硬性拒绝，不靠模型理解放行。

## 持久性与来源撤销

`goal-replan` 记录失败快照、方案、独立审查、模型会话与版本；执行图应用在单个 SQLite 事务内完成。`goal-plan-dispatch` 保证同一方案对同一原任务只发送一次继续指令。崩溃后未完成的只读规划工作可重新排队；有副作用的 Worker 命令仍遵守原有不确定状态处理。

正常关闭宿主时，中断的只读规划/审查不再被记为目标失败。已有方案保留，job 回到 pending，重启后重新执行未完成的独立审查；不会重新发出已完成的方案或重复创建任务。人工暂停和来源失效仍走原有失效检查。

规划开始前即绑定来源上下文，覆盖成功、拒绝、中断和过期结果。目标读取同时检查历史规划上下文，因此较早保存、尚未回填目标上下文的拒绝记录也受撤销限制。新建通知只给出通用未完成提示；详细说明通过带来源校验的目标读取提供，避免排队通知携带已撤销文档的摘要。此修复不重写旧实现已经保存的通知内容；本次中间版本均未部署，没有把旧验收数据库升级为日常服务。

这里的“独立”指不同会话和受限只读工具，仍可使用同一个模型/backend；不能据此保证判断误差相互独立。自然语言授权的语义审核仍可能出错；宿主硬性保护合同字段、资源范围、执行状态、证据完整读取与最终验收门槛。

## Review 与兼容性

采用 `practical-code-review` 和 Codex Security 差异审查。首次不可变快照审查发现并复现一项撤销后派生摘要可读问题；修复后继续检查历史记录与通知，补齐来源保护。真实运行和针对性回归还发现并修复通知未稳定、blocked 自动输入扣留、审查中途关闭被误记为失败、未完成任务的执行记录被活动窗口淘汰四处推进问题。关闭恢复及记录淘汰的回归均先在旧实现失败，再在修复后通过。

活动清理现在保留所有未结束任务的元数据，避免其他 Router/审查活动改变任务证据；任务结束后恢复最近 200 条普通历史的清理规则。仍不保存提示词、工具参数或返回内容；已经被旧实现淘汰的记录不会被伪造补回。这项修正意味着长任务期间保留的元数据会随实际操作量增长。

后续真实任务还推动补齐依赖证据，并将返工/重规划额度分别传给审查模型。新增回归先证明下游只能看到自己的 1 份台账，修正后能看到四个相关任务；另一项回归证明审查中途改动上游产物会使下游结果 stale，而不会发布报告。该修正保留原标准，只补足判断所需的证据。

数据库 schema 保持不变，新增的是记录类型和可选字段。没有不可变合同的既有目标不会自动获得重规划授权；旧目标的原有调度保持，需新建明确授权的结构化目标使用该能力。旧程序不理解新中间节点和重规划 job，不能把“schema 未变”当作可直接降级运行；保留原版本及其数据库备份进行回退，工作文件和已经发生的外部效果不由数据库回退撤销。
