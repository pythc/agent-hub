# Roppo 人格、记忆与工作方法

## 使用入口

- **Agent 团队 → 基本配置**：分别设置 Router 和 Worker 的名称、身份介绍、性格与表达、职责与提示词。人格文件可导入到草稿，统一保存后生效。
- **行为规则 → 通用规则**：设置团队共同性格。单个 Agent 的人格与职责仍保留在成员配置中。
- **设置 → 记忆**：默认汇总当前账号的个人记忆，也可切换到单个群聊。左侧选择条目，右侧查看内容、来源和修订，直接编辑或删除。

字号沿用工作台现有规范。文件页签为 MEMORY.md、USER.md、SOUL.md、IDENTITY.md、AGENTS.md；工作方法、整理、导入导出位于“更多”。窄屏使用列表与详情切换。

## 数据职责

| 内容 | 权威存储 | Markdown 视图 | 更新方式 |
| --- | --- | --- | --- |
| 名称、身份 | revisioned execution 配置 | IDENTITY.md | 人工编辑或文件导入后保存 |
| 单个 Agent 性格 | execution.router/workers.persona | SOUL.md | 人工编辑或文件导入后保存 |
| 单个 Agent 职责 | execution.router/workers.prompt | AGENTS.md（人格文件） | 人工编辑或文件导入后保存 |
| 团队共同性格 | prompts.personality | 配置导出 | 通用规则中保存 |
| 用户信息、偏好 | memory-fact 及来源、版本 | USER.md | 显式记忆、自动学习、文件导入 |
| 长期事实 | memory-fact | MEMORY.md | 有来源的自动提取与整理 |
| 经验证的工作经验 | memory-fact，origin=experience | MEMORY.md 中的经验条目 | 任务验收后的经验提取 |
| 协作方式 | 当前可见的偏好和经验的派生视图 | ALIGNMENT_SYNTHESIS.md | 从有效记忆实时组成 |
| 可复用工作方法 | skill-version、skill-lifecycle、原任务验收 | SKILL.md | 从已验收任务保存、试用、验收、停用 |

Markdown 是导入/导出的视图，不建立另一套后台可变文件。记忆页的 AGENTS.md 与团队页使用相同的 Router 职责配置，工作经验在 MEMORY.md 中展示。

## 人格生效

统一提示词组装包含团队共同性格、Agent 身份与性格、Agent 职责。预览、实际调用和运行中指令刷新复用同一个渲染函数。后端默认人格可由成员配置覆盖。未配置人格时，Router 使用 Roppo 默认身份和自然、简短、略带俏皮的表达方式。简单问题简短回答，复杂任务再展开；这不会减少实际执行与验证。自定义人格继续优先，Worker 不自动继承 Router 的默认性格。人格影响表达与工作风格，任务角色、可用工具和已有任务授权仍由运行时配置决定。

配置沿用 Settings 的版本比较和历史。团队页文件导入先进入草稿；记忆页文件编辑显式保存，导入文件直接应用。保存时若宿主配置已改变，保留编辑内容并提示刷新。API 导入必须提交预期 revision。

## 个人记忆与学习

`/api/chat/memory` 根据已登录用户重新解析其 Chat 会话与入口。个人入口只接受该用户的 ChatRun；群聊入口继续要求管理上下文。读取、编辑、导出和技能操作都会重新检查入口与来源。入口没有运行上下文时不会构造虚假的记忆空间；旧宿主未启用管理范围时，继续使用既有范围迁移流程。

记忆条目显示内容、适用情况、来源原文和历史。编辑保留来源关系并比较 revision。记忆不再经过用户确认队列。来源校验通过的提取、整理和经验直接生效；不支持的猜测、过时替换和自动删除建议归档，不覆盖人工修订。删除记忆沿用持久撤销与遗忘机制。来源删除或历史清理后，协作方式和导出内容会随当前有效记忆变化。

“从交流中学习”控制自动写入模式。关闭后保留已保存记忆和手工操作，重新打开会恢复原来的 auto/adaptive 模式。页面刷新通过显式 refresh 操作整理当前可管理入口的旧候选，不改变学习策略，也不额外调用模型。GET 查询保持只读。导入的记忆文件直接创建有来源的有效条目。

协作方式直接展示当前可见偏好和工作经验，最多 12 条，不额外维护无来源的模型总结。实际任务仍使用现有有预算的记忆检索与上下文清单，不重复塞入一份完整摘要。

## 任务复盘

- 成功复盘依赖宿主最终验收记录，而不是 Worker 自报成功。
- 目标因验收失败或证据不足进入 held 时，可提取失败尝试的经验；取消任务不会作为失败学习。
- 提取结果必须有适用条件和来源中的精确引文。有依据的失败教训可直接成为记忆，不改变原任务状态，也不把失败步骤标为成功。
- 最近的验收轮次和实际执行证据供提取使用，不从日志缺失推断根因或成功结果。
- 同一目标和验收轮次去重。复盘证据与观察任务在同一个数据库事务内写入。观察队列沿用租约、重试、每日调用预算、重启恢复与原始来源删除链。

## 工作方法演化

通过最终验收且包含本地 Worker 计划的任务会出现在可保存的方法列表中，不为生成候选重新执行任务。

1. 从原任务原样保存的固定方法可沿用该任务的验收证明。
2. 编辑步骤、目标、参数或恢复旧版本时，保存为新的版本。修改版需在一次明确请求的实际任务中试用。
3. 宿主确认该版本的实际任务通过最终验收后，该版本显示为可用。页面显示该版本的通过次数和验收未通过次数。
4. 停用只针对选定版本，阻止新的手动、计划及事件任务启动；已经开始的任务保留其原契约。
5. 自动化固定引用 id/version，不会随新版本保存而变化。计划与事件当前只接受已验收、未停用、无未绑定参数的固定方法。

参数使用 `{{name}}`，在页面按 `name = 名称` 声明。支持目标、步骤、计划、产物路径和文本验收内容；不替换 Worker、依赖拓扑、验收 ID 或权限字段。运行时要求提供全部已声明参数，拒绝额外参数、嵌套占位符和不合法的文件路径。运行请求沿用原对话的明确请求及稳定 operationId。

SKILL.md 导出用于阅读和交流，包含版本、参数、步骤与验收条件；实际执行读取数据库中的完整模板。

## 升级与恢复

原记忆 ID、来源、权限、学习策略和技能历史保留。新技能语义及失败复盘写入时将 SQLite 格式提升到 14，防止旧宿主忽略“待试用/已停用”状态与失败复盘记录。代码项目写入不会把数据库版本降回 13。

升级前保留既有备份。回退代码前核对数据库兼容性，不手工降低 `user_version`，也不为回退代码覆盖当前业务数据库。记忆遗忘仍由现有独立撤销记录约束恢复行为。

## 验证

自动化测试覆盖实际提示词与预览一致、个人账号隔离、有效记忆导入去重、并发修订、旧候选整理、同源条目的独立编辑、学习模式恢复、失败经验重启、参数化方法验收、版本保留和停用后的执行阻止。浏览器验证使用独立数据库与模拟模型，不调用用户的模型服务或修改现有运行数据。

验证记录见本次实现的 design-qa.md 与独立浏览器 fixture 的 evidence.json。

复现浏览器检查时，用 `MEMORY_BROWSER_DIR` 指定独立目录，运行 `npx tsx examples/agent-memory-browser.ts`，再用同一目录运行 `tests/browser/agent-memory.py`。该 fixture 的任务和验收数据用于界面检查；实际 Worker 执行与最终验收流程由自动化测试覆盖。

## 重置个人记忆

在“设置 → 聊天”选择“清空所有记忆和上下文”，确认后清空当前账号的对话、记忆、复盘经验、从任务保存的工作方法及学习过程记录，个人学习策略恢复默认。后续对话使用新的入口身份，重新进入冷启动状态。浏览器中的对应草稿、待发送消息和会话资源状态一并清理。

登录、模型连接、插件、群聊配置和手动设置的人格保留。相关旧任务停止，旧执行的迟到结果不能重新写回。重置记录持久化到撤销日志；重启或恢复旧数据库备份时仍执行清理。完成后新设置的学习策略不会被清理重试覆盖。
