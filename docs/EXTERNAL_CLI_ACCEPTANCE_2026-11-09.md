# 外部 CLI 与 GitHub 插件验收 — 2026-11-09

本轮使用真正的 `kind: plugin` Codex 执行后端，完成了此前原生后端通过的同一 CSV 长任务。Router、Worker 和独立验证器均经过沙箱插件进程，没有切换到原生后端兜底。

## 排查结论与修复

旧记录确认了两条不同的失败路径：一次 Router 在取得原生会话 ID 前失败；发布路径则留下了 `pushing` 状态和未确认工具回执。旧传输层将异常压缩成 `process_failed` 或 `outcome_unknown`，原始 RPC、超时或退出信息没有保留。因此，不能把模型目录请求超时、网络波动等同期现象直接写成已证实的根因。

本轮补齐并验证了以下改动：

- 失败记录保留操作阶段、有限的原因枚举、已知原生 RPC 方法及错误码、进程退出码。Provider 正文、stderr、工具参数和凭据不进入诊断字段。
- 初始化失败也会留下诊断记录。已确认的账号探测超时属于推理前只读失败，按 `transient` 处理；探测期限从 15 秒调整为 60 秒。执行或发布中断仍保留不确定状态。
- 未确认工具副作用不仅阻止重启后的重试，也阻止同一轮用新调用 ID 再次执行。新增负向测试验证：适配器吞掉第一次错误后，第二次调用仍被宿主拦截。
- Codex 参考包升级为 `1.0.1`，状态协议仍为 1，原有会话绑定、摘要固定、授权、长期目标和验收机制保留。

这些修复解决了可观测性缺口和同轮重试边界；本轮成功不代表旧故障的底层原因已被完整复原，也不是高并发可靠性保证。

## 真实任务结果

专用私有仓库的 [Issue #9](https://github.com/pythc/agenthub-github-validation/issues/9) 与 [草稿 PR #10](https://github.com/pythc/agenthub-github-validation/pull/10) 完成了全流程。受控任务先产生真实测试失败，再提交一次错误的完成结果，要求宿主独立拦截并返工；冻结测试和验收标准始终不变。

[脱敏证据](evidence/external-cli-github-2026-11-09.json) 的 **24 项检查全部通过**：

- 始终只有一个目标、一个任务；停机期间的原 Issue 评论和失败 CI 在重启后被接收并续接原任务。
- Worker 复用原生会话；错误完成报告被拒绝，随后在同任务、同 PR 上自动返工一次。
- 节点和总体独立验收通过后才释放结果。5 个外部插件会话、44 个工具回执全部确认，未遗留失败记录或不确定副作用。
- GitHub 来源包经过 `1.0.0 → 1.1.0 → 1.0.0`，安装 revision 为 `1 → 2 → 3`。升级包执行了不同的探测代码；回滚保留当前数据库与历史。
- 四个宿主进程的实现哈希一致。草稿 PR 在总体验收后关闭，从未合并。
- 运行结束后通过外部插件只读回查全部 5 个原生会话，ID 均与持久化绑定一致，分别保留 3、3、3、1、1 轮历史。

CI 是实际执行冻结测试后回写 GitHub Commit Status，未运行托管 GitHub Actions。升级回滚在任务排空后进行。本轮没有部署或重启现有 Roppo 服务。
